# 需求变更 (Update - Asset Management)

## 1. 样式调整
- **问题**: 盘点界面（AssetDetail.tsx）在移动端底部被导航栏挡住，“删除资产”与“保存修改”看不见。
- **方案**: 为页面或表单底部增加足够的 `padding-bottom` (如 `pb-32`) 或重构底部 Action Bar 增加底部安全区边距（`safe-area-inset-bottom`），避免被全局 NavBar/浏览器底栏遮挡。

## 2. 状态选项更新
- **问题**: 需要移除“正常”状态，保留/增加“损坏”。
- **方案**: 
  - 更改表单下拉选项，调整为：`待盘点`, `已盘点`, `报废`, `维修`, `损坏`。
  - 由于目前的 SQLite 数据库可能针对 `status` 有固定的限制要求，前端调整后若后端存取有报错需一并兼容旧数据。

## 3. 布局顺序调整
- **问题**: 资产照片的位置应当放在“归属管理”之后。
- **方案**: 修改 `AssetDetail.tsx` 的布局顺序。将包含图片上传的模块移至“主要表单（基础信息 + 归属管理）”下方，优化表单填写逻辑顺序。

## 4. 扫码与 OCR 合并 & OCR 容错机制 & 识别率优化
- **问题**: 目前 OCR 设计与“扫码/核查”分散；识别率不高；OCR 出错直接要求重试，用户无法手动修改错字。
- **方案**: 
  1. 将 OCR 整合到核查主页面（`Scan.tsx`），作为核查资产的一种新手段。
  2. OCR 识别模式切换：在开启 OCR 时，**切换至拍摄单张高清照片或从相册上传图片**的模式，不再使用实时视频流模糊截帧，以此大幅提高 AI 识别准确率。
  3. 容错与手动修改：如果扫码（二维码/条码）或 OCR 后未找到该资产（触发 `notFound` 状态），在弹出的提示框中，将原先仅作为文本展示的识别结果**改为 `input` 文本框**，允许用户直接修改一两个错误字符，然后点击“再次匹配”，无需重新拍摄。

## 5. 组织、部门与位置支持“智能下拉”
- **问题**: 资产组织、管理部门、位置仅能打字输入，易错且不方便。目前后端报错导致功能失效。
- **方案**: 
  - **后端修复**: 修复 `/api/assets/metadata/options` 的 SQL 语句。由于 `assets` 表中不直接存储字段名而是 ID，需通过 `LEFT JOIN` 获取名称或直接查询 `organizations`/`departments` 主表。
  - **前端增强**: 确保 `<datalist>` 的 ID 与 `input.list` 属性严格对应，修复因之前的绑定 ID 包含中划线或大小写不敏感导致的浏览器识别问题（推荐使用下划线）。

## 7. OCR 自动填充与差分比对 (Auto-fill & Diff)
- **问题**: OCR 识别后跳转到详情页没有自动填充，或者已有资产无法直观看到哪些字段被 AI 修改了。
- **方案**: 
  - **自动填充**: 在从 `Scan.tsx` 跳转至 `AssetDetail.tsx` 时，通过 `location.state` 携带识别出的完整 JSON (`ocrData`)。详情页组件在挂载时若检测到该数据，则自动覆盖 `formData`。
  - **差分可视化 (Diff)**: 
    - 记录 `originalData`（数据库原始值）。
    - 对比 `formData` 与 `originalData`。如果某字段被 OCR 覆盖导致内容变化，该输入框应用“AI 主题色”（如浅紫/浅蓝背景）标注。
    - 在变更字段旁显示“原值”提示和一键重置“X”按钮，方便用户快速纠回。
  - **模型显示**: 在 UI 显著位置（如扫码页或详情页标题旁）显示当前的 OCR 模型名称，增加系统透明度。

## 6. OCR 报错排查与降级修复 (413 Payload Too Large)
- **问题**: OCR 传输图片时报错 `413 Request Entity Too Large` 导致 Server Error。原因是 Base64 编码的高清图片提及过大，超出了前后端传输或 Nginx/Express 的默认 Body 大小限制。
- **方案**: 
  - **后端前端双管齐下**：
    - 前端在向后端发送 Base64 图片之前，利用 Canvas 进行客户端侧压缩（按最大分辨率 1080p、画质 0.8 处理），减小请求体体积。
    - 后端在 Express 初始化 `app.use(express.json({ limit: '10mb' }))` 以防 Node 层级拒绝大型 payload。
  - 为 AI OCR 接口补充更细致的 `try-catch` 控制，当 API Key 失效或请求被阻拦时给出友好的兜底提示，而非页面崩溃。
