# 详细设计：RBAC 部门隔离、调拨流与自动维护机制

为“操作员 (operator)”角色引入严格的部门隔离机制，并配套规范的调拨流与“自动化”的部门管理界面。

## 核心需求
1.  **部门 ID 匹配核心化**：
    *   所有权限基于 `departments.id`。
    *   **新增资产自动维护**：无论是在手动新增页面还是 Excel 导入，若输入的部门名称在系统中不存在，后端将**自动创建**该部门并生成 ID，确保业务流不中断。
2.  **多部门管辖与展现翻译**：
    *   **翻译机制**：前端在显示“管辖范围”和资产卡片时，通过全局 ID-Name 映射将数字翻译为名称。
    *   **数据导出还原**：导出的 Excel 文件必须通过 SQL `JOIN` 将 `dept_id` 还原为人类可读的部门名称。
3.  **跨部门调拨申请流**：
    *   操作员发现非本部门资产（通过扫码）时，可点击“申请调拨”，提交事由至管理员处审批。在此期间，该资产对操作员仅显示脱敏后的简略信息。
4.  **融合式部门管理（集成于人员管理页面）**：
    *   管理员在管理用户部门权限时，可直接进行以下操作：
        *   **新增**：点击顶部 “+” 图标按钮。
        *   **更名/删除**：点击条目右侧的控制图表。
        *   **合并**：多选部门后，点击“合并”并**输入新部门名称**。合并后，旧部门的所有资产将自动归属及关联到新部门。
5.  **权限精控**：
    *   操作员禁止直接新增资产，禁止查看全局审计日志和管理其他用户信息。

## 实施细节

### 数据流动逻辑
*   **导出逻辑**：`SELECT a.*, d.name AS dept_name FROM assets a LEFT JOIN departments d ON a.dept_id = d.id`，输出 `dept_name` 至 Excel。
*   **写入逻辑（Asset POST/Excel Import）**：
    1. 接收到 `dept_name` (string)。
    2. 检查 `departments` 表。
    3. 若存在，获取 `id`；若不存在，`INSERT` 并返回 `id`。
    4. 将 `id` 写入 `assets.dept_id`。

### 部门合并逻辑
*   **接口**：`POST /api/departments/merge`。
*   **参数**：`{ sourceIds: number[], newName: string }`。
*   **原子操作**：
    1. 创建/获取 `newName` 的部门 ID。
    2. 执行 `UPDATE assets SET dept_id = [NEW_ID] WHERE dept_id IN ([SOURCE_IDS])`。
    3. 删除旧的部门条目。

## 安全与隔离
*   **默认拒绝**：若操作员没有任何部门授权，其所有资产操作均返回 403。
