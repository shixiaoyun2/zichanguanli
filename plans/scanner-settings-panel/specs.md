# 扫码器高级设置面板规范 (Specs)

## 1. 功能概述
在扫码页面增加一个设置面板，允许用户自定义扫码器的解码引擎和支持的条码格式。这有助于在特定环境下（如特定格式的条码识别不准或效率低时）优化扫码体验。

## 2. 设置项定义
### 2.1 条码格式过滤 (Format Selection)
- **目标**：锁定特定的条码格式以提高识别效率和准确度。
- **支持格式**：从 `Html5QrcodeSupportedFormats` 中选取常用格式，包括但不限于：
  - `QR_CODE` (二维码)
  - `EAN_13` (商品条码 - 默认首选)
  - `CODE_128` (物流/资产条码)
  - `CODE_39` (工业条码)
  - `EAN_8`
  - `UPC_A`
- **默认值**：`[EAN_13, QR_CODE]`。
- **行为**：多选框列表。若不选任何项，则默认支持所有。

### 2.2 解码引擎选择 (Engine Selection)
- **目标**：选择底层解码库，以解决某些特定库识别乱码或不准确的问题。
- **选项**：
  - **默认 (Zxing-js)**：库自带的解码器，兼容性最好。
  - **原生 (BarcodeDetector API)**：使用浏览器/操作系统的原生 API。效率极高，但在部分 PC 浏览器上不支持（主要支持 Android/iOS 的现代浏览器）。
- **默认值**：由 `html5-qrcode` 库自行决定（通常优先使用 BarcodeDetector，若不支持则降级）。设置项应允许显式强制或手动选择。
- **注意**：`html5-qrcode` 的 `useBarCodeDetectorIfSupported` 选项可以控制此行为。

## 3. 持久化 (Persistence)
- 所有设置将保存至 `localStorage` (Key: `scanner_settings`)。
- 页面加载时自动从缓存读取并应用于扫码器初始化。

## 4. UI 交互设计
- **触发器**：扫码页面右上角放置一个“齿轮”图标。
- **面板形式**：底层抽屉 (Bottom Sheet) 或 居中模态框 (Modal)。
- **实时性**：修改设置后需提示用户点击“重新扫描”以应用更改，或者自动清空并重建扫码器实例。

## 5. 技术细节
- 使用 `localStorage` 存储 JSON 对象。
- 在 `useEffect` 的扫码器实例化逻辑中，读取 `localStorage` 的值并注入配置参数。
