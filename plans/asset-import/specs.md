# 资产导入与字段扩展设计规范

## 1. 功能目标
优化资产导入流程，使其完美适配用户提供的 Excel 模板（`asset-import-test.xlsx`），并扩展资产表字段以支持位置、备注和规格等信息。

## 2. 字段扩展计划

在 `assets` 表中新增以下字段：

| 数据库字段 | Excel 列名 (模板) | 说明 |
| :--- | :--- | :--- |
| `location_name` | 位置名称 | 资产存放的具体地理位置 |
| `remarks` | 备注 | 额外的说明信息 |
| `model` | 规格型号 | 资产的详细技术指标、规格或型号 |

**保留/映射现有字段 (完整对应模板)：**
- `org_name` <- `资产组织`
- `card_code` <- `卡片编号`
- `asset_code` <- `资产编码`
- `name` <- `资产名称`
- `remarks` <- `备注` (新增)
- `barcode` <- `条形码`
- `model` <- `规格型号` (新增)
- `location_name` <- `位置名称` (新增)
- `dept_name` <- `管理部门`
- `user` <- `使用人`
- `序号` -> (自动忽略，仅作行号参考)

## 3. 导入逻辑优化 (Excel Import)

### 3.1 映射处理
- 自动识别 Excel 中的中文字头。
- 如果 Excel 中缺少某个字段，则该字段在导入时设为空。
- 丢弃 Excel 中多余的列（如“序号”）。

### 3.2 冲突检测增强
- 当通过 `asset_code` 匹配到已有资产时，不仅对比旧字段，还要对比 `location_name`, `remarks`, `model` 是否发生变化。
- 若 `updated_at` (最后修改时间) 在 Excel 中存在且晚于库中时间，标记为 `OVERWRITE`。
- 若存在差异且无法确定先后，标记为 `CONFLICT` 供用户手动选择。

## 4. UI 表现

### 4.1 资产详情页 (AssetDetail.tsx)
- 新增“位置”、“规格型号”和“备注”编辑项。
- 采用与现有表单一致的卡片风格布局。

### 4.2 资产列表页 (AssetList.tsx)
- **预览弹窗**：在导入预览表格中增加“位置名称”列，方便用户核对。
- **列表显示**：在桌面端列表视图中，考虑在“部门/组织”下方展示“位置名称”。

## 5. 导出逻辑同步
- 导出的 Excel 文件应包含新增的三个字段，确保“导入-编辑-再导出”链路的数据完整性。
